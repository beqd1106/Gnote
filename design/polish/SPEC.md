# Gnote 既存問題の手直し仕様（G検定 学習アプリ）

## なぜ直すか
いまの問題は **「一番長い選択肢を選ぶ」だけで56%正解できる**。正解だけ説明が丁寧で長く、誤答が短い言い換えになっているため。
これでは知識がなくても解けてしまい、練習で実力が測れない。また解説の多くが100字未満で、答えの言い換えで終わっている。

## 入力と出力
- 入力：`polish/<レッスンID>.json`（そのレッスンの既存問題の配列）
- 出力：`polish_out/<レッスンID>.json` に、**直した問題だけ** を次の形で配列にする。

```json
{ "id": "（元のID）", "choices": ["…","…","…","…"], "explanation": "…", "wrongChoiceExplanations": {"1":"…","2":"…","3":"…"} }
```
- **選択肢の並び順と正解の位置（correctAnswers）は変えない**。設問文・beginnerNote・その他のキーは出力しない（変えない）。
- 直す必要がない問題は出力に含めない。

## 1. 選択肢の長さをそろえる（対象：正解が4つの中で一番長い、または一番長いものと同点の問題）
- 目標：**正解が一番長くならない**ようにし、4つの字数差を目安10字以内にする。
- やり方は2つを組み合わせる：
  - **正解を刈り込む**：意味を変えずに、余計な修飾や言い換えを削る（正解の中身＝何が正しいかは絶対に変えない）。
  - **誤答を肉付けする**：誤答に具体的な説明を足して長さをそろえる。足す内容は **G検定の範囲に実在する別の手法・用語・概念の正しい説明** にする（誤答は「この設問の答えとしては誤り」だが、書いてある説明自体はでたらめにしない）。
- 正解を短くしすぎて、逆に「一番短いものが正解」という癖を作らない。
- 誤答が正解にもなってしまう（複数正解になる）書き方をしない。

## 2. 解説を直す（対象：explanation が100字未満の問題）
- **「結論／その手法・概念が何をするものか／混同しやすい隣との区別」の3点構成で100〜200字**。
- 区別の一文は、誤答に出てくる手法・用語との違いを書くと効果が高い。
- 選択肢を直した問題は、解説と誤答解説（wrongChoiceExplanations）も新しい選択肢の内容に合わせる。

## 事実の正確さ（必須）
- **年・人名と年の対応・法律の条番号・施行日・数値を新しく書かない**。元の問題・レッスン資料（<レッスンID>.md）にあるものだけ使う。
- 自信のない事実は足さない。
- 解説や誤答解説で「選択肢①」「1番目」のように位置を書かない（位置はあとで入れ替わることがある）。

## 作業の進め方（必須・守らないと制限で全損する）
- 1レッスンの対象を **5〜8問ずつ** 直し、そのたびに `polish_out/<レッスンID>.json` を上書き保存する（それまでの分も含めた配列で）。
- 長い調査はしない（Web検索は不要）。
- 最後に短いスクリプトで検算して報告：直した問題数、直したあとで「正解が一番長い（同点含む）」問題の数、解説の最小字数。
- 自分の担当以外のファイルには触れない。作業用スクリプトを作るなら名前に担当レッスンIDを入れる。
