# Gnote「基礎問題」作成仕様（G検定 ジェネラリスト検定 学習アプリ）

## 目的
各レッスンの確認問題の前に解く **「基礎問題」を各レッスン10問** 作る。
レッスン本文を一度読んだ初学者が **7〜9割解ける** 難易度にする。

## 難易度と中身（最重要）
- 問うのは、そのレッスンの **本文の柱となる概念・用語・手法の役割**。1問1論点。
- **10問はすべて別々の論点にする**。同じ事実を言い回しだけ変えて何度も問わない。
- 論点は **レッスン本文から取る** のを基本とし、足りなければ同レッスンのテーマに直結する G検定シラバス（syllabus_gkentei_2024.txt）の基本事項から取る。**レッスンのテーマから外れた論点は使わない**。
- 設問は短く（60字以内目安）。「〜とは何か」「〜の説明として正しいものはどれか」「〜したいときに使う手法はどれか」「AとBの違いとして正しいものはどれか」型を基本にする。
- 誤答は **明らかに別物だが無関係ではない** もの（同じ分野の別の手法・用語）。ひっかけ・部分的に正しい誤答・「〜のみ」「必ず」の揚げ足取りは使わない。
- 単一選択のみ（correctAnswers は要素1つ）。選択肢は必ず4つ。

## 事実の正確さ（必須）
- **年・人名と年の対応・法律の条番号・施行日・数値を新しく書かない**。使ってよいのは、パケット内の既存問題かレッスン本文にすでに出てくるものだけ。
- 手法名・人名・法律名は正式な表記で。自信のない事実は使わず、論点を差し替える。
- 各問に `basis`（根拠のメモ。「レッスン本文『〜』」または「シラバス『〜』」を1文）を付ける。確認用でアプリには入らない。

## 選択肢の「長さの癖」を作らない（必須）
- 4つの選択肢の字数をそろえる（最長と最短の差は目安で10字以内）。**正解が一番長くならないよう** 意識する。
- 正解位置は 0/1/2/3 をレッスン内で散らす（10問なら 3/3/2/2 程度）。
- 設問文に正解の語をそのまま含めない。

## 解説
- `explanation`：**「結論／それが何をするものか／混同しやすい隣との区別」の3点構成で100〜200字**。
- `wrongChoiceExplanations`：誤答3つそれぞれに、それが実際には何なのかを1文で（キーは "0"〜"3" の文字列、正解のキーは入れない）。
- `beginnerNote`：答えを書かずに着眼点を示す1文（ヒントとして表示される。**正解の語もその言い換えも含めない**）。

## 既存問題との重複禁止
パケット末尾の既存問題と、設問＋正解が実質同じになる問題は作らない（同じ論点を、より基本的な別の角度から問うのはよい）。

## 出力形式
`out/<レッスンID>.json` に JSON 配列。

```json
{
  "id": "b-hist1-01",
  "question": "…",
  "choices": ["…","…","…","…"],
  "correctAnswers": [2],
  "explanation": "…",
  "wrongChoiceExplanations": {"0":"…","1":"…","3":"…"},
  "domain": "hist",
  "service": "<テーマ名。既存問題の [ ] 内の名前から最も近いものを使う>",
  "difficulty": 1,
  "tags": ["基礎", "<テーマ名>"],
  "beginnerNote": "…",
  "basis": "…"
}
```
- id は `b-<レッスンIDの l- を除いた部分>-01`〜`-10`（例：l-dlb2 → b-dlb2-01）。domain はパケット冒頭の domain。

## 作業の進め方（必須・守らないと制限で全損する）
- 1レッスンにつき **Write を2回**：まず5問（-01〜-05）を書いて out/<レッスンID>.json を作成、次に10問全部で上書き。1回の出力を小さく保つ。
- 長い調査はしない（Web検索は不要）。レッスン資料・シラバス・自分の確かな知識で書く。
- 1レッスン書き終えたらすぐ次へ。検算は最後にまとめて短いスクリプトで行う（正解が単独最長の問題数・正解位置・解説の最小字数）。
- 自分の担当以外のファイルには触れない。作業用スクリプトを作るなら名前に担当レッスンIDを入れる。

# 【今回の作業】この節が上の記述より優先する

## 背景
レッスンの「基礎問題」と「確認問題」は、それぞれ **5問ずつ パターンA/B/C（計15問）** で出題する形に変わった。
既存の問題で15問に足りない分を新しく作る。**作る数と id はパケット冒頭「今回作る問題」に書いてある通り**にする（id の -01〜-10 という記述は無視）。

## 基礎問題（id が b- で始まるもの）
- 上の仕様どおり（difficulty 1・tags に「基礎」）。
- そのレッスンの基礎問題（既存＋今回）は **すべて別々の論点** にする。既存の基礎問題・確認問題・ランダム問題と論点が重ならないよう、レッスン本文の柱のうち **まだ問われていないもの** を探す。足りなければ同じ概念を別の角度（目的→名前、名前→役割、似たものとの違い）から問う。

## 確認問題（id が qc- で始まるもの。無いレッスンもある）
- 本試験に近い難易度（difficulty 2）。パケットの「既存の確認問題」の形式・難しさに合わせる。
- tags に「基礎」を入れない（tags は ["<テーマ名>"]）。それ以外の項目・解説・長さの癖のルールは基礎問題と同じ。
- 設問は1〜2文の状況設定があってよい。単一選択・4択。

## 正解位置
- 今回作る問題の正解位置を 0/1/2/3 でばらけさせる（同じ位置が3回以上続かない）。

## 出力と作業の進め方（必須）
- 出力は `out/<レッスンID>.json`。そのレッスンで今回作る **基礎と確認をまとめて1つの JSON 配列** にする。
- **5問書くごとに Write で上書き保存**（1回の出力を小さく保つ。途中で止まっても成果が残るように）。
- Web検索はしない。パケット・仕様にある資料と自分の確かな知識で書き、自信のない論点は使わない。
- 担当レッスンを書き終えたら、各レッスンについて「問題数・正解位置の分布・正解が単独最長の問題数・解説の最小字数」を短く報告する。
- 担当以外のファイルには触れない。

## 逆向きの「長さの癖」も作らない（必須）
- 正解を一番長くしないことを意識しすぎて、**正解が一番短い** 問題が多くなりがち。これも見分け方になってしまう。
- レッスンで作る問題全体で、正解が「一番長い」のは4問に1問程度、「一番短い」のも4問に1問程度にする。残りは中間の長さ。
